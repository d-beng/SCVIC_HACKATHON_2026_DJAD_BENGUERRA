tracking with collision detection on Quanser Interactive Labs simulation

Run from the repository root, in order:

```
python code/task1_detection.py
```

written into `results/` and overwrite the included precomputed results
identically (all files are rewritten from scratch on each run).

## 2. Overall design

The three tasks form a two-stage system:

1. **Learn the map from clean data.** The individual-vehicle videos each
   contain exactly one car driving one route, so every detection
   unambiguously belongs to that car. Six videos therefore yield six
   trajectories = the six roads (Tasks 1-2).
2. **Use the map as prior knowledge on dirty data.** In the multi-vehicle
   videos, YOLO fails exactly where tracking is hardest (merged boxes in
   collisions, debris detections, identity ambiguity). Knowing that
   vehicles can only travel along six known roads lets the tracker predict
   where a lost vehicle must be and restore its identity on re-detection
   (Task 3).

## 3. Task 1 - Vehicle detection (vehicle_coordinates.csv)

For every frame of every individual-vehicle video, the provided YOLOv11
model is run and each detection's centralized location (bounding-box
center) is logged, together with the box corners and confidence.

**Banner handling.** Each video carries a black "Provided by Quanser"
banner with red text. Its height is measured automatically per video: a
pixel is banner-like if it is near-black or strongly red; a row belongs to
the banner if >50% of its pixels are banner-like in *every* of 5 frames
sampled across the video (per-row minimum across samples, so dark moving
scene content cannot fool the measurement). The measured strip (+10 px
margin) is cropped before inference and detection coordinates are shifted
back to original full-frame pixel space, so all outputs share one
coordinate system.

**False-positive rejection.** Early experiments showed two YOLO failure
modes: (a) very large phantom boxes on dark building facades, and
(b) ghost detections on the road surface where headlight glow falls.
(a) is rejected geometrically: any box wider or taller than 25% of the
frame cannot be a car in this top-down view (real cars measure ~9% of
frame width; the largest observed real box was ~23% during headlight
bloom, phantoms exceeded the threshold). (b) is handled downstream
(Task 2 dedup / Task 3 duplicate merge), because a confidence threshold
could not separate them: ghosts scored up to 0.69 while genuine but
partially occluded vehicles scored as low as 0.40 - hence the detection
threshold is kept low (0.25) and filtering is geometric instead.

**Outputs:** `results/task1/vehicle_coordinates.csv`
(`video_index, video_name, frame_index, center_x, center_y, x1, y1, x2,
y2, confidence`), plus annotated frames and an annotated video per input.

## 4. Task 2 - Road map (roads_defined.json)

Each video's detections are converted into one smooth road centerline:

0. **Dedup:** the individual videos contain exactly one car, so only the
   highest-confidence detection per frame is kept (removes headlight
   ghosts).
1. **Gap-aware outlier removal:** a point is rejected if it jumps further
   from the previous kept point than MAX_JUMP_PX x (frame gap). Measured
   frame-to-frame displacement: median 4.8 px, p99 13.3 px; one erroneous
   97 px jump in the raw data is removed by this filter.
2. **Arc-length resampling** to 200 evenly spaced points - this also
   closes gaps left by missed detections (cars in deep shadow
   occasionally drop below the detection threshold for a few frames).
3. **Savitzky-Golay smoothing** (window 41, order 3). An automatic
   noise-based spline criterion (s = n*sigma^2 with sigma estimated from
   second differences) was evaluated but over-smoothed tightly curved
   segments; the fixed window validated visually against the scene
   imagery was retained.
4. **Endpoint extrapolation:** each end is extended along the direction of
   its last 20 points until it reaches near a frame border, satisfying the
   requirement that roads start/end near the edges. Roads are capped at
   y=300 (below the banner), i.e. at the edge of the *observable* scene.
5. **Final resample + light smoothing** removes the joint between the
   measured curve and the extrapolated tail.

**Empty template.** No empty scene image was provided, so one is
synthesized: per-pixel temporal median over ~150 frames sampled across all
six videos. With a static camera, any given pixel shows a moving object
in only a small fraction of samples, so the median recovers the empty
road. The template is saved as `empty_template.jpg`, referenced by the
JSON, and used as the background of the verification overlay.

**Output schema** (as specified in the hackathon slides):

```json
{
  "image": {"template_path": "empty_template.jpg", "width": W, "height": H},
  "roads": [
    {"road_id": 0, "num_trajectories": 1,
     "centerline": [{"x": ..., "y": ...}, ...]},
    ...
  ]
}
```

Verification artifacts: `roadmap_plot.png` (raw detections vs smoothed
roads) and `roadmap_overlay.jpg` (all roads drawn on the empty template).

## 5. Task 3 - Consistent tracking, prediction, collision detection

**State per vehicle (track):** position, velocity, bounding box, permanent
ID, associated road, ordered road history, a LOCKED travel direction along
the road, locked speed, and a missed-frame counter.

**Per-frame loop:**

1. *Advance.* Every track moves one frame forward: constant velocity while
   healthy; while lost, it WALKS ITS ROAD's centerline in the locked
   direction at the locked speed - this is the predicted likelihood
   coordinate of a lost vehicle required by the task, and it is drawn on
   the video (PRED marker).
2. *Detect.* YOLOv11 with the same banner crop and phantom filter as
   Task 1, plus a duplicate merge: detections closer than 45 px keep only
   the highest confidence (headlight ghosts).
3. *Match,* staged so that confirmed vehicles always outrank new
   candidates (a debris detection can never steal a real vehicle's box):
   - Stage A: confirmed active tracks, tight 45 px gate, closest pairs
     first - prevents ID swaps when vehicles cross;
   - Stage B: confirmed coasting tracks, gate growing with lost duration;
   - Stage C (RESCUE): a remaining detection within 180 px of a lost
     vehicle is given to that vehicle, never born as a new ID. For the
     first 12 missed frames (the collision window) the rescue requires
     the detection to lie on the vehicle's REMEMBERED road - two colliding
     cars therefore cannot exchange identities; afterwards the road
     requirement softens to a cost penalty (where two roads run close
     together, nearest-road becomes ambiguous and must not block
     recapture);
   - Stage D: unconfirmed candidates receive only what is left.
4. *Road memory.* A vehicle's associated road is (re)assigned only while
   it is healthy - detected this frame and not inside a collision. While
   lost or colliding the road is frozen, so the vehicle remembers where it
   was and can only be recaptured there.
5. *ID management.* A new track earns an ID instantly only at a road entry
   point with no confirmed vehicle within 300 px (a detection appearing
   next to an existing vehicle in an entry/exit zone is a duplicate, not a
   new car); anywhere else it must survive 6 consecutive frames, which
   collision-debris detections do not. ADOPTION: when a candidate is about
   to be confirmed, it first searches for a lost confirmed vehicle within
   300 px - if found, it inherits that vehicle's ID, road, and direction
   instead of creating a new identity ("after re-detection, restore the
   vehicle id"). State explosions are prevented by resetting velocity
   along the remembered road after any recapture (a recapture jump is not
   a real velocity) and clamping speed to 25 px/frame (~2x the measured
   p99).
6. *Collision detection.* Two confirmed vehicles whose centers
   approach within 55 px are flagged: red boxes, a full-width
   "COLLISION DETECTED: ID a & ID b" banner on the video, a per-frame
   collision flag in the CSV, and a console report of the first collision
   frame per pair.

**Anomalies observed and the rule each one motivated:**

| Symptom (from logs)                          | Root cause                                            | Rule added                                  |
|----------------------------------------------|-------------------------------------------------------|---------------------------------------------|
| Phantom IDs born during collisions           | debris detections survived probation                  | staged matching, candidates matched last    |
| Track retired at (-3098,-81)                 | recapture jump interpreted as velocity                | velocity reset on recapture + speed clamp   |
| Lost vehicle reborn with a new ID            | rescue gate missed the re-emerging detection          | RESCUE stage (180 px) + ADOPTION rule       |
| Two colliding cars swapped IDs               | rescue by pure distance                               | road-memory hard constraint during collision|
| Duplicate ghost near an exit got instant ID  | headlight duplicate inside a road-entry zone          | entry fast-track blocked near any vehicle   |

**Visualization** (matching the reference style): dark label bar
`ID n HR[a,b] Pk` (ID, last two roads of the history, present road),
white H-marker at the vehicle center, solid trail (past), dotted path with
`F-Rk` label (predicted future along the road), PRED circle while the
position is predicted, semi-transparent colored road network with labels
on every frame, and the collision banner.

**Output:** `results/task3/tracking_results.csv`
(`video_index, video_name, frame_index, vehicle_id, associated_road, x, y,
state (detected|predicted), collision (0|1)`), plus tracked frames and a
tracked video per input.

## 6. Parameter justification

Every threshold comes from one of three sources: a MEASUREMENT on this
data, a specific LOGGED FAILURE that motivated it, or a VISUAL/engineering
choice validated against annotated frames and overlays. Two measured
anchors recur throughout: the motion statistics (frame-to-frame
displacement median 4.8 px, p99 13.3 px) and the car size in this
top-down view (~45-55 px, ~9% of frame width, max observed ~23% during
headlight bloom).

### Detection (Tasks 1 and 3)

- `CONF_THRESHOLD = 0.25` - true vehicles partially occluded at frame
  edges or in shadow scored as low as 0.40, while ghost detections scored
  up to 0.69; a confidence cut cannot separate them, so the threshold is
  kept low and filtering is geometric instead.
- `MAX_BOX_FRACTION = 0.25` - real cars measure ~9% of frame width (max
  observed ~23%); larger boxes are necessarily phantoms, so this filter
  cannot reject a true vehicle. Validated: rejected every phantom across
  all videos, never the real car.
- Banner parameters (5 sampled frames, 50% banner-like row fraction,
  10 px margin) - derived from the banner's visual properties (black
  background + red text -> low green/blue channels); per-row minimum
  across samples makes moving dark scene content unable to fool it.

### Task 2 - road construction

- `MAX_JUMP_PX = 80` per frame gap - ~6x the measured p99 displacement;
  removed the one erroneous 97 px jump in the raw data while keeping all
  real points (the allowance scales with detection-gap length so points
  after a gap are not wrongly discarded).
- `SMOOTH_WINDOW = 41, SMOOTH_POLY = 3` - selected visually: smaller
  windows left jitter in low-light road segments. An automatic spline
  criterion (s = n*sigma^2, sigma from second differences) was evaluated
  and rejected: it over-smoothed tightly curved segments.
- `RESAMPLE_POINTS = 200` - ~10 px spacing between road points, fine
  enough for nearest-road association in Task 3, compact in the JSON.
- `END_DIR_POINTS = 20`, final 11-point smoothing pass - eliminated the
  kink between the measured curve and the extrapolated tail (a logged
  74 deg max-turn artifact on road 0).

### Task 3 - matching gates

- `GATE_ACTIVE = 45 px` - validation radius for healthy tracks: ~3x the
  worst-case real per-frame movement (p99 13.3 px) plus box-center
  jitter; generous enough never to lose a detected car, tight enough
  that two crossing cars cannot fall into each other's gates and swap
  (lowered from 60 specifically as an anti-swap measure).
- `GATE_GROWTH = 5 px` per missed frame - a lost car's position
  uncertainty grows by roughly one frame of motion (median speed
  ~5 px/frame) per frame lost.
- `RESCUE_GATE = 180 px` - recapture radius; logged successful rescues
  occurred at 59-143 px, so 180 covers the observed worst case with
  margin.
- `HARD_ROAD_MISSED = 12` frames - the window in which a rescue strictly
  requires the vehicle's remembered road. Logged collision losses lasted
  1-7 missed frames, so 12 covers the collision window; beyond it the
  requirement softens to a cost penalty, because in parallel-road
  sections nearest-road becomes ambiguous and a strict requirement caused
  a logged false refusal (duplicate-ghost creation).
- `ROAD_MISMATCH_PENALTY = 250` - dominates any in-gate distance, so a
  same-road detection is always preferred when available.

### Task 3 - track life-cycle

- `MIN_HITS = 6` frames probation - collision-debris detections flickered
  for fewer than 6 consecutive frames in the logs; real cars persist
  trivially (raised from 3 after debris survived the original probation).
- `MAX_MISSED = 50` frames - outlasts the longest observed occlusion
  (~15 frames) while letting departed cars expire; raised from 30 after a
  logged retire-and-rebirth cycle.
- `ROAD_ENTRY_DIST = 120 px` - the zone around road endpoints where new
  cars genuinely appear: ~one car length plus endpoint-extrapolation
  noise.
- `ADOPT_GATE = 300 px` - how far a confirming candidate searches for a
  lost vehicle whose ID it should inherit; upper-bounds the drift between
  a coasting prediction and the true re-detection. Deliberately the
  loosest gate: a false adoption requires a lost vehicle and a new birth
  to coincide, which is nearly impossible.
- `MAX_SPEED = 25 px/frame` - hard physical clamp at ~2x the measured
  p99; added after a logged state explosion (track retired at
  (-3098,-81) after a recapture jump was misread as velocity).

### Task 3 - detection hygiene and collision

- `DUP_MERGE_DIST = 45 px` - headlight-ghost duplicates appeared within
  ~one car length of the true box; two genuinely distinct cars never run
  that close outside a collision, which is handled separately.
- `COLLISION_DIST = 55 px` - two box centers within ~one car length means
  physical contact in this top-down view; tuned on the collision videos:
  fires during the crashes, not during ordinary close driving.


## 7. Limitations & future work

The tracker follows standard multi-object-tracking principles (gated
association, probationary track initiation, occlusion coasting) and is
deliberately specialized to this task's priors: a static camera, a single
vehicle class, and a known road network, as the task intends. Thresholds
are calibrated to this dataset. Natural generalizations are a Kalman
filter motion model, Hungarian assignment, and appearance-based
re-identification (DeepSORT) - appearance features would add little here,
as the simulated vehicles are visually near-identical, which is precisely
why the road-map prior is the discriminative signal in this scene.
